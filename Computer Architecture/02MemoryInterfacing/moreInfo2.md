# Advanced Memory Systems: Cache and Virtual Memory

## 1. The Memory Hierarchy
The memory system is structured as a hierarchy to balance **speed, cost, and capacity**.
* **Registers:** Fastest, smallest capacity, located inside the CPU.
* **Cache Memory (L1, L2, L3):** High-speed semiconductor memory using Static RAM (SRAM) to store frequently used data.
* **Main Memory (RAM):** Slower than cache, uses Dynamic RAM (DRAM), holds active programs.
* **Secondary Storage (SSD/HDD):** Slowest, largest capacity, non-volatile.

---

## 2. Cache Memory Principles
Cache works on the principle of **Locality of Reference**:
1. **Temporal Locality:** If a memory location is accessed once, it is highly likely to be accessed again soon (e.g., loops).
2. **Spatial Locality:** If a memory location is accessed, nearby locations are likely to be accessed soon (e.g., arrays, sequential code execution).

* **Cache Hit:** The CPU finds the requested data in the cache.
* **Cache Miss:** The data is not in the cache; the CPU must fetch it from main memory, causing a delay.

---

## 3. Cache Mapping Techniques
Main memory is divided into **blocks**, and cache memory is divided into **lines** (or slots). Mapping determines how a main memory block is placed into a cache line.

### A. Direct Mapping
* **Concept:** Each block of main memory maps to exactly one specific cache line.
* **Formula:** `Cache Line Number = (Main Memory Block Number) MOD (Total Lines in Cache)`
* **Address Structure:** Split into three fields:
  * **Tag:** Identifies which specific main memory block currently occupies the cache line.
  * **Line Offset/Index:** Specifies the exact cache line.
  * **Word/Block Offset:** Specifies the exact byte within that block.
* **Pros & Cons:** Simple and inexpensive to implement, but suffers from high conflict misses (thrashing) if two active blocks map to the same line.

### B. Fully Associative Mapping
* **Concept:** Any block of main memory can be loaded into any available cache line.
* **Address Structure:** Split into only two fields:
  * **Tag:** Uniquely identifies the block.
  * **Word/Block Offset:** Identifies the specific byte.
* **Pros & Cons:** Highly flexible with zero conflict misses, but requires expensive hardware (comparators) to search all cache tags simultaneously.

### C. Set-Associative Mapping
* **Concept:** A compromise between Direct and Fully Associative. Cache lines are grouped into **Sets**. A memory block maps to a specific set (Direct style), but can occupy any line within that set (Associative style).
* **Address Structure:** Split into **Tag**, **Set Index**, and **Word Offset**.
* **Example:** In a "2-way Set-Associative Cache," each set contains 2 lines.

## 4. Cache Write Policies
When the CPU updates data in the cache, that change must eventually reflect in the main memory to maintain data integrity.

* **Write-Through:** Data is written to both the cache and the main memory simultaneously.
  * *Pro:* Main memory always has valid, updated data.
  * *Con:* Slower because writing to main memory creates a bottleneck.
* **Write-Back (Copy-Back):** Data is updated only in the cache. A **"Dirty Bit"** is set to `1`. The main memory is updated only when that cache line is about to be replaced by another block.
  * *Pro:* Fast execution because memory writes are minimized.
  * *Con:* Main memory contains stale data until the write-back occurs.

---

## 5. Cache Coherence
In multi-core processors, each core has its own private L1/L2 cache, but they share a single main memory. **Cache Coherence** ensures that if Core A modifies a shared variable, Core B does not read an old, stale version of that variable from its own cache.

### Common Coherence Protocols
* **Snooping Protocols:** Each core monitors (snoops) the shared bus to see if other cores are modifying memory addresses that it currently holds in its local cache.
* **MESI Protocol:** A widely used 4-state snooping protocol:
  * **M (Modified):** Cache line is valid but dirty (different from main memory).
  * **E (Exclusive):** Cache line matches main memory and is present *only* in this cache.
  * **S (Shared):** Cache line matches main memory and exists in other caches too.
  * **I (Invalid):** Cache line contains no valid data.

---

## 6. Virtual Memory & Paging
Virtual memory is a management technique that makes the system appear to have much more main memory than it physically does by utilizing secondary storage space.

* **Key Concepts:**
  * **Logical/Virtual Address:** The address generated by the CPU/Program.
  * **Physical Address:** The actual hardware address in the RAM.
  * **Memory Management Unit (MMU):** The hardware component that translates virtual addresses to physical addresses at runtime.
* **Paging:** Virtual memory is broken into fixed-size blocks called **Pages**, and physical RAM is broken into matching blocks called **Frames**.
* **Page Table:** A table stored in RAM that maps a virtual Page to its physical Frame.
* **Translation Lookaside Buffer (TLB):** A small, ultra-fast hardware cache inside the MMU that stores recent page table translations to speed up address resolution.
* **Page Fault:** Occurs when the CPU requests a page that is not currently loaded into physical RAM. The OS must halt execution and fetch the page from the hard drive/SSD.
